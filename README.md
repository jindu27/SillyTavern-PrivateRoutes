# 多线群聊 · Private Routes

给 SillyTavern 1.19.0 的群聊加入 AI 主卡和独立剧情。你只和主卡互动。主卡可以在同一轮内联系多张副卡，每张副卡都只根据自己的角色设定及与主卡的经历生成回应。

## 安装

1. 启动 SillyTavern，连接可用的模型。
2. 打开顶部的「扩展」→「安装扩展」，粘贴：

       https://github.com/jindu27/SillyTavern-PrivateRoutes

3. 安装完成后刷新页面。打开一个由多张角色卡组成的群聊，在输入框上方勾选「多线群聊」，再从主卡列表中选择一张或多张主卡。
4. 照常在酒馆输入框发消息。扩展开关和主卡按群聊保存，每个聊天存档单独记录剧情。

### 关系世界书

仓库的 `worldbooks/关系演进-陆时路野.json` 是一份独立世界书，包含关系演进总则、冲突与修复规则，以及团子、陆时和路野的详细相处档案。先在酒馆的世界书管理中导入它，再在多线群聊的「关系世界书」列表中选择一份或多份。扩展会把公共规则提供给主卡和副卡，并按条目的 `extensions.privateRoutes.target` 只把对应角色档案提供给主卡或对应副卡。

这是一个前端扩展。模型生成复用酒馆当前的连接，适合能稳定输出 JSON 的模型。连接的生成长度需要足够容纳一轮分段回复。扩展使用自己的对话编排和上下文，角色卡文本会参与生成。原生群聊的历史不会直接并入副卡私线。需要使用世界书时，在扩展的「关系世界书」列表中选择已经导入酒馆的世界书，扩展会按条目的常驻标记、关键词和 `extensions.privateRoutes.target` 为主卡或对应副卡注入规则。

安装「用户身份 · Narrative Identities」扩展后，用户身份会由剧情文本自动创建、切换和揭露。多线扩展会为当前身份保存独立的私线历史和关系状态，统一在团子状态栏中显示本体、小号和其他角色，回复区块会按当前身份显示 `@你` 或 `@小号`。升级身份插件后，已有的旧 `$user` 好感度会迁移到“你”身份。

## 一轮怎么进行

- 主卡可以对玩家和多张副卡分别行动。输出按对象分块，无动作显示「主卡本轮无行为」。
- 选择多张主卡时，它们共享同一个剧情规划器，但保留各自的角色设定、口吻和输出来源。
- 被主卡联系的副卡必须回应。其余副卡可以自己发消息或跳过。主卡根据剧情决定立即接话几次，或等下一条玩家消息。输入框右侧的停止按钮可以取消正在生成的整轮并保留输入。生成期间会在聊天底部逐段显示已经完成的 `@` 区块，整轮保存后再替换为正式消息。
- 约定见面仍属于线上。剧情确实见面时进入线下约会，可以持续多轮。其他人默认跳过可见互动，时间继续经过，只有明确且重要的事件才形成一条待处理来信，主卡约会结束后在同一轮按对象集中补回。
- 剧情时间从第 1 天开始，随叙事推进。例如「吃完饭已经九点了」可以推动其他角色在这段时间里行动。页面打开或关闭的实际时长不推进剧情。

界面上你能看到所有分线。每次向副卡请求生成时，只提供它的角色卡、主卡名称、这一条线的近期历史和提供给它的行为。玩家的话和其他分线的内容不会自动并入。主卡可以在剧情中主动转述。其他会修改所有模型请求的扩展可能改变这项行为。

如果主卡包含 `【团子状态】` 规则，扩展会把好感度和执念保存到当前群聊的状态中，并在一轮回复的底部显示一次状态栏。状态栏使用当前群成员名称，兼容旧的 `aff_zhouye` 变量名。这里的流式显示按分线完成顺序更新，模型请求仍然以结构化小步骤生成。

扩展还会保存每条关系的关系模式、熟悉度、阶段、张力和未解决问题。新聊天使用 `new` 模式，已有聊天历史使用 `ongoing` 模式。主卡可以通过 `relationship_updates` 更新这些关系状态，熟悉度范围为 0-100，张力范围为 0-4，也可以用 `resolve_issue` 清除已经解决的问题。世界书负责描述角色的缺点、边界、冲突方式、正向推进和独立生活，扩展只处理通用状态和私线注入，不包含任何固定角色名。

### 当前预设自动分层

多线模式使用 `generateRawData` 自己的编排，因此扩展会在每次主卡或副卡请求前读取当前 Chat Completion 预设的 `prompt_order`。扩展只取当前实际启用的条目，跳过 `marker` 上下文占位符、聊天历史、角色卡字段、世界书占位和空条目，并保留其余行为、文风和输出规则的原角色顺序。预设中的 `{{char}}`、`{{user}}` 等宏会按当前主卡或副卡上下文解析。

读取到的预设消息会放在本轮结构化任务之前；随后再追加私线隔离和 JSON 结构约束。预设文风只约束 `actions[].text` 与 `messages[].text` 等内容字段，不能改变外层 JSON。无需手工复制预设文本。

当玩家明确写出“让某张副卡做什么”“@某张副卡”“要求某张副卡回应”时，主卡规划器会生成 `side_directives`。目标副卡会在自己的私线生成中收到一条导演指令，并被要求本轮必须回应。普通剧情描述、没有点名的愿望和模糊暗示不会触发导演指令，副卡继续按原有的人设与私线规则自行决定是否行动。玩家原话不会直接发送给目标副卡，只有提取后的指令会进入该副卡请求。

不满意上一轮时，可以直接点击酒馆的重新生成按钮。扩展会回退到上一轮之前的状态重新生成，生成失败或停止时保留原回复。格式校验失败会重试一次。模型失败或本轮停止时，可重新发送留在输入框里的消息。分线和待回复状态保存在对应的群聊存档，生成时会按上下文长度使用近期记录。当前仅处理文本。
